# 005. 특약 순번은 계약 행 비관적 락으로 정한다

- 상태: 적용 (프로젝트 기간)
- 커밋: `75a381a`, `ce8aa19`

## 상황

특약에는 계약 안에서의 순번(`order_no`)이 있고, "현재 특약 개수 + 1"로 정합니다.

채권자와 채무자가 협상 중에 동시에 특약을 추가하면, 둘 다 개수를 3으로 읽고 둘 다 4번을 붙일 수 있습니다.

## 검토한 선택지

| 선택지 | 판단 |
|---|---|
| `(contract_seq, order_no)` 유니크 + 충돌 시 재시도 | 재시도 로직이 따로 필요하고, 충돌은 사용자에게 오류로 보임 |
| 낙관적 락 | 충돌하면 결국 재시도 처리가 필요함 |
| **계약 행을 `PESSIMISTIC_WRITE`로 읽고 추가** | 채택 |

## 결정

특약 추가·수정·삭제와 계약 수정은 계약 행을 `SELECT ... FOR UPDATE`로 읽고 시작합니다. 같은 계약의 작업은 한 줄로 서서 처리됩니다.

자동이체에서는 락을 쓰지 않았는데 여기서는 쓴 이유는 작업 성격이 달라서입니다.

- 외부 호출 없이 DB 안에서 짧게 끝납니다. 락을 잡는 시간이 짧습니다.
- 한 계약에 동시에 접근하는 사람은 당사자 두 명뿐이라 대기가 거의 없습니다.
- 자동이체는 은행 응답을 기다려야 해서 락을 오래 잡게 되므로 맞지 않았습니다 ([001](001-conditional-update-claim.md), [002](002-transfer-outside-transaction.md)).

## 감수한 것

- AI 특약 추가는 계약 행 락을 잡은 채 AI 서버를 호출합니다. AI 응답이 늦으면 그동안 같은 계약의 다른 특약 작업이 기다립니다. "외부 호출 없이 짧다"는 위 근거와 맞지 않는 부분이라, AI 호출을 락 밖으로 빼는 것이 남은 개선점입니다.
- 순번 중복을 DB 제약으로 막지는 않습니다. 락을 거치지 않는 새 경로가 생기면 중복이 날 수 있습니다.
