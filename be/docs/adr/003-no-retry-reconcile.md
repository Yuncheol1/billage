# 003. 결과를 모르는 이체는 다시 보내지 않고 거래내역으로 확정한다

- 상태: 적용
- 커밋: `a6f3e1d`, `8f5ca24`, `a37c226`

## 상황

은행에 이체를 보냈는데 응답 타임아웃이 나면, 돈이 나갔는지 알 수 없습니다. 요청은 은행에 닿았고 답만 못 받았을 수 있습니다.

이걸 실패로 보고 다음 실행에서 다시 보내면 이중 출금이 될 수 있고, 성공으로 보면 실제로 안 나간 돈을 받은 것으로 기록합니다.

## 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 실패로 보고 재시도 | 이중 출금 위험 |
| 같은 거래 식별자로 재시도 (은행이 중복을 걸러주길 기대) | SSAFY 금융 API의 거래 고유번호는 호출마다 새로 만드는 값이고, 같은 번호로 보내면 중복을 걸러준다는 문서가 없음. 전제를 확인할 수 없어 버림 |
| 즉시 거래내역 조회 | 은행에 반영되기 전에 조회하면 "안 나갔다"고 잘못 판단할 수 있음 |
| **처리중으로 두고 일정 시간 뒤 거래내역과 대조** | 채택 |

처음에는 같은 식별자로 재시도하는 방향을 생각했습니다. 하지만 구현하면서 은행이 중복을 막아준다는 근거를 찾을 수 없었고, 근거 없는 전제 위에 출금을 올릴 수는 없다고 판단했습니다.

## 결정

1. 은행 응답을 세 가지로 나눕니다. 성공, 확정 실패(은행이 처리하지 않은 것이 확실), 결과 불명.
2. 결과 불명이면 회차를 처리중으로 둡니다. 클라이언트는 재시도하지 않습니다.
3. 이체할 때 적요에 `BL{회차번호}`를 넣어 둡니다.
4. 다음 자동이체 실행 시작 시, 처리중으로 10분 넘게 남은 회차를 채무자 계좌 거래내역에서 찾습니다.
5. 표식과 금액이 맞는 거래가 1건이면 납부, 0건이면 미납(기한 지났으면 연체), 2건 이상이거나 조회 실패면 자동 판정하지 않습니다.
6. 자동 판정하지 못한 건은 알림을 보내고, 사람이 운영자 API로 확정합니다 ([운영 런북](../runbook.md)).

분류 기준과 대조 규칙의 세부 표는 [auto-transfer.md](../auto-transfer.md)에 있습니다.

## 감수한 것

- 결과 불명이 나면 그 회차는 최소 다음 실행(4시간 뒤)까지 확정되지 않습니다. 사용자 입장에서는 납부가 늦게 보입니다.
- "10분이면 거래내역에 반영된다"는 가정에 기댑니다. SSAFY 금융 API에서 반영 시간을 측정하지는 않았습니다.
- 2건 이상 매칭은 시스템이 중복 출금인지 같은 금액의 다른 거래인지 구분하지 못합니다. 하나를 골라 확정하면 오류가 드러나지 않고 남기 때문에 사람에게 넘깁니다.
- 중복 출금이 확인되더라도 환불을 처리하는 기능은 없습니다.
