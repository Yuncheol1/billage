# 트러블슈팅

직접 겪고 고친 문제를 증상, 원인, 해결, 확인 방법 순서로 남깁니다.

---

## 1. 분기·반기·연간 상환 일정이 틀어짐

- 커밋: `96f39b5` (2026-10-13)

### 증상

원금 120만 원, 연 12%, 12개월 분기 상환(4회차)으로 계약을 만들면:

- 1·2회차 원금이 0원이고, 3회차에 원금 120만 원이 한꺼번에 들어감
- 4회차는 원금·이자 모두 0원
- 이자 합계가 108,000원 (정상은 90,000원)

반기·연간 상환은 일반적인 기간으로는 계약 생성 자체가 거절됐습니다.

### 원인

`totalInstallments`의 단위를 앱과 서버가 다르게 보고 있었습니다.

- 앱은 **회차 수**를 보냅니다. 12개월 분기 상환이면 4.
- 서버는 이 값을 **개월 수**로 읽었습니다. 루프를 4번 돌면서 `i % 3 == 0`인 회차에만 원금을 넣었고, 원금 분할도 `4 / 3 = 1`로 계산했습니다.
- 검증도 `회차 수 < 주기 개월`을 비교해서, 반기 12개월(2회차)은 `2 < 6`으로 거절됐습니다.

월 상환은 주기가 1개월이라 회차 수와 개월 수가 같아서 문제가 드러나지 않았습니다.

### 해결

프론트는 그대로 두고 서버를 앱 기준(회차 수)에 맞췄습니다.

- 회차 수만큼 루프를 돌고, 매 회차 원금을 균등 분할합니다.
- 이자는 남은 원금 기준으로 주기 개월치를 계산합니다.
- 검증은 "계약 기간이 상환 주기 한 번 이상인가"로 바꿨습니다.

### 확인

`ContractServiceRepaymentScheduleTest`에 분기·반기·연간·월 상환 케이스를 추가했습니다. 월 상환은 수정 전과 결과가 같은지 회귀 테스트로 고정했습니다.

### 배운 것

같은 이름의 필드라도 보내는 쪽과 받는 쪽이 단위를 같게 보는지 확인해야 합니다. 서버 코드만 읽었을 때는 "루프가 개월 수만큼 돈다"고 잘못 진단했고, 앱 코드에서 값을 만드는 부분을 보고서야 원인을 찾았습니다.

## 2. 은행이 HTTP가 아닌 응답을 보내면 이체 결과가 분류되지 않음

- 커밋: `91298a9`, `ea9e94f` (2026-10-14)

### 증상

WireMock으로 은행 장애를 재현하는 테스트를 쓰다가 발견했습니다. 은행 서버가 HTTP가 아닌 쓰레기 바이트를 돌려주면, 이체 클라이언트가 결과 불명으로 분류하지 않고 예상하지 못한 예외를 그대로 던졌습니다.

### 원인

클라이언트는 `RestClientException`만 잡아서 결과 불명으로 바꾸고 있었습니다. HTTP가 아닌 응답은 상태 코드를 읽는 단계에서 `IllegalArgumentException`이 나서 이 분류를 빠져나갔습니다.

요청은 이미 은행에 보낸 뒤라 돈이 나갔을 수 있는데, 상위 코드는 이걸 일반 오류로 처리했습니다.

### 해결

요청을 보낸 뒤 나는 나머지 `RuntimeException`도 결과 불명으로 분류했습니다. 모르는 예외는 실패로 단정하지 않는다는 원칙([ADR 003](adr/003-no-retry-reconcile.md))을 그대로 적용한 것입니다.

### 확인

`SsafyTransferApiClientWireMockTest`에서 타임아웃, 연결 끊김, 5xx, 깨진 응답을 각각 재현해 분류를 확인합니다.

### 배운 것

Mock으로 쓴 단위 테스트는 "내가 예상한 예외"만 던지기 때문에 이런 구멍을 못 잡습니다. 실제 HTTP 통신을 흉내 내는 가짜 서버를 쓰고 나서야 드러났습니다.

## 3. 수동 완료와 연체 전환이 처리 중인 이체를 덮어씀

- 커밋: `fa594e6`, `bfe19f0` (2026-10-13)

### 증상

코드를 검토하다가 찾았습니다. 실제로 발생한 기록은 없습니다.

자동이체가 회차를 처리중(`REQUESTED`)으로 바꾼 직후, 채권자가 "직접 받았음"을 누르면 회차가 `MANUAL_PAID`로 덮어써집니다. 은행 이체도 나가고 현금 수령도 기록되어, 채무자가 두 번 낸 셈이 됩니다.

09:30 연체 전환도 같은 문제가 있었습니다. 처리중을 연체로 덮어쓰면 돈은 나갔는데 회차는 연체로 남습니다.

### 원인

이체 쪽은 조건부 UPDATE로 바꿨지만, 수동 완료와 연체 전환은 여전히 "엔티티를 읽고 확인한 뒤 값을 바꾸는" 방식이었습니다. 확인과 저장 사이에 다른 요청이 상태를 바꿔도 알 수 없습니다.

### 해결

두 경로도 조건부 UPDATE로 바꿨습니다.

- 수동 완료: `NONPAID`, `OVERDUE`일 때만 `MANUAL_PAID`
- 연체 전환: `NONPAID`일 때만 `OVERDUE`

이어서 납부 확정(자동이체 성공, 수동 이체 성공, 대조 결과)도 `REQUESTED`일 때만 `PAID`로 바꾸게 했습니다. 바뀐 행이 0이면 상환 이벤트와 알림을 남기지 않고 끝납니다.

연체 전환은 팀원이 작성한 코드라 확인을 받고 수정했습니다.

### 확인

`RepaymentManualTransferServiceTest`, `RepaymentNotificationSchedulerTest`에서 UPDATE 결과가 0일 때 상태와 부수 효과가 바뀌지 않는지 확인합니다. 실제 경합은 `RepaymentScheduleConcurrencyTest`에서 MySQL 컨테이너로 확인합니다. 이체 선점과 수동 완료·연체 전환을 동시에 보내 30번 반복해도 매번 한쪽만 이깁니다. 상태 조건을 빼고 돌리면 테스트가 실패하는 것도 확인했습니다.

### 배운 것

동시성 규칙은 한 경로만 고치면 의미가 없습니다. 같은 행을 바꾸는 모든 경로를 찾아서 같은 규칙을 적용해야 합니다.

## 4. 차용증 PDF에 한글 폰트가 등록되지 않음

- 커밋: `48d8f51` (2026-03-25)

### 증상

차용증 PDF를 만들 때 한글 폰트를 렌더러에 등록하지 못해 한글이 나오지 않았습니다.

### 원인

Flying Saucer는 CSS 웹폰트만으로 한글을 그리지 못해서, 폰트 파일 경로를 렌더러에 직접 등록해야 합니다. 이 경로를 `ClassPathResource.getFile()`로 얻고 있었습니다.

IDE에서 실행하면 리소스가 실제 파일로 있어서 동작하지만, jar 안의 리소스는 파일 시스템 경로가 없어서 `getFile()`이 실패합니다.

### 해결

애플리케이션 시작 시(`@PostConstruct`) 폰트를 스트림으로 읽어 임시 파일로 복사하고, 그 경로를 렌더러에 등록했습니다.

### 배운 것

클래스패스 리소스는 파일이 아니라 스트림으로 다뤄야 실행 방식에 상관없이 동작합니다.

## 5. 알림 실패가 이미 나간 이체 기록까지 롤백함

- 커밋: `47ec295` (2026-09-08)

### 증상

당시 자동이체는 회차 여러 건을 한 트랜잭션으로 처리했는데, 이체 성공 뒤 FCM 알림 전송에서 예외가 나면 같은 트랜잭션의 이체 기록이 전부 롤백될 수 있었습니다.

돈은 나갔는데 회차는 미납으로 남아, 다음 실행에서 다시 이체됩니다.

### 원인

알림은 이체의 부수 효과인데, 이체 기록과 같은 트랜잭션 안에서 예외를 그대로 던지고 있었습니다.

### 해결

1차로 알림 예외를 잡아 로그만 남기도록 했습니다.

이후 근본적으로는 이체 API 호출을 트랜잭션 밖으로 빼고 회차마다 따로 처리하는 구조로 바꿨습니다 ([ADR 002](adr/002-transfer-outside-transaction.md)). 알림 말고도 예외가 날 곳은 많았기 때문입니다.

### 배운 것

외부로 나간 행위(송금)는 DB 롤백으로 되돌릴 수 없습니다. 예외를 하나씩 막는 것보다, 되돌릴 수 없는 일을 트랜잭션 밖으로 빼는 쪽이 구조적으로 안전합니다.
